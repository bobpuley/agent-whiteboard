Consult `git log -- docs/02_assumptions-and-risks.md docs/04_architecture.md` around the v0.26 release for that history if needed.)
> **Versioning note:** the milestone label (`vX.Y`, this table's first column) and `package.json`'s published `version` are two independent numbering schemes — the milestone label tracks planning/task progress, not release significance. `package.json`'s semver bump instead follows standard semver semantics based on what actually shipped: patch for fixes/internal hardening with no new user-facing capability, minor for new backward-compatible functionality, major for a breaking change. Under this rule, milestones v1.0–v1.5 (all fixes/hardening, no new capability) correctly shipped as `1.0.x` patches; v1.6 (new user-facing export/import functionality) is the first to ship as a minor, `1.1.0`. (This superseded the original "package.json stays on a 1.0.x patch train regardless of milestone label" phrasing — see `02`'s v1.6 section, 2026-09-07.)

> When scoping a new milestone, skim the **Design Debt Log** in `01_input-ideas.md` for candidates worth promoting into a real task — it's a running list of non-behavioral findings (duplication, test gaps, hardening, style polish) that don't get pulled into planning automatically.
